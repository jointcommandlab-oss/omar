# دليل إعداد الخلفية (Supabase) — بالعربية البسيطة

هذا الدليل لشخص غير مبرمج ويعمل من الآيفون (Safari). كل الخطوات من المتصفح فقط. الخطوات مجانية في البداية. لا يوجد أي دفع حقيقي في التطبيق.

## 1) إنشاء مشروع Supabase مجاني
1. افتح Safari وادخل على supabase.com ثم اضغط Start your project.
2. سجّل الدخول (يمكنك استخدام GitHub أو البريد).
3. اضغط New project. اختر اسماً مثل cycling-ae.
4. اختر كلمة مرور قوية لقاعدة البيانات واحفظها في مدير كلمات المرور (لا ترسلها لأحد).
5. اختر المنطقة الأقرب (مثلاً Frankfurt أو Mumbai) واختر الخطة Free ثم Create.
6. انتظر دقيقتين حتى يكتمل التجهيز.

## 2) تشغيل ملف SQL
1. من القائمة افتح SQL Editor ثم New query.
2. افتح الملف `supabase/migrations/0001_init.sql` من GitHub (زر Raw)، انسخ كل محتواه والصقه.
3. اضغط Run. يجب أن تظهر رسالة Success. إن ظهر خطأ لا تعد التشغيل مرتين؛ أرسل نص الخطأ للمطوّر.
4. للتأكد: افتح Table Editor وستجد الجداول (routes, products, events...) وبجانب كل جدول علامة RLS مفعّلة.
5. افتح Storage وستجد 4 مجلدات صور: route-images, product-images, listing-images, avatars. الحد الأقصى للصورة 5 ميغابايت (الصورة الشخصية 2) والأنواع المسموحة JPEG وPNG وWebP فقط.

## 3) نسخ مفاتيح الاتصال
1. افتح Project Settings ثم API (أو Data API).
2. انسخ قيمتين فقط:
   - Project URL
   - anon public key (المفتاح العام)
3. لا تنسخ ولا تستخدم أبداً المفتاح المسمّى service_role داخل التطبيق أو Cloudflare Pages للواجهة. هو مفتاح سري يتجاوز كل الحماية.

## 4) إضافة المتغيرات في Cloudflare Pages
1. ادخل dash.cloudflare.com ثم Workers & Pages ثم مشروع الموقع.
2. Settings ثم Variables and Secrets (Environment variables).
3. أضف متغيرين لبيئة Production (وكرر لـ Preview إن أردت):
   - `VITE_SUPABASE_URL` = قيمة Project URL
   - `VITE_SUPABASE_ANON_KEY` = قيمة anon key
4. احفظ ثم افتح Deployments وأعد النشر (Retry deployment) كي تُقرأ المتغيرات.
5. ملاحظة: إن لم تضف المتغيرين يعمل الموقع بالبيانات التجريبية دون أي خطأ.

## 5) تعيين أول مدير (خطوة آمنة، ليست تلقائية)
لا يصبح أي شخص مديراً بمجرد التسجيل أولاً. التعيين يتم يدوياً منك فقط:
1. سجّل حساباً عادياً في الموقع ببريدك (أو من Authentication ثم Users ثم Add user).
2. افتح SQL Editor وشغّل التالي بعد استبدال البريد ببريدك الحقيقي:

```sql
insert into public.user_roles (user_id, role)
select id, 'admin' from auth.users
where email = 'your-email@example.com'
on conflict do nothing;
```

3. تأكد أن النتيجة "1 row" وليس صفراً (صفر يعني أن البريد غير مسجّل أو مكتوب خطأ).
4. هذه الخطوة تعمل فقط من SQL Editor لأنه يستخدم صلاحيات المالك. لا يستطيع أي مستخدم من التطبيق تعديل جدول الأدوار.
5. لإزالة مدير: `delete from public.user_roles where user_id = '...';`

كل إجراء إداري مهم يجب تسجيله في جدول admin_audit_logs (يُسمح بالإضافة والقراءة فقط للمدراء، ولا حذف ولا تعديل).

## 6) إعداد المصادقة (Authentication)
- Authentication ثم URL Configuration: ضع رابط موقعك في Site URL وأضفه في Redirect URLs.
- فعّل تأكيد البريد الإلكتروني (Confirm email).

## 7) حدود الخطة المجانية وتكاليف محتملة لاحقاً
الأرقام تتغير؛ راجع supabase.com/pricing قبل الاعتماد عليها. تقريباً في الخطة المجانية:
- قاعدة بيانات نحو 500 ميغابايت، وتخزين ملفات نحو 1 غيغابايت، ونحو 50 ألف مستخدم نشط شهرياً.
- يتم إيقاف (Pause) المشروع المجاني بعد فترة طويلة بلا نشاط (نحو أسبوع)، ويمكنك إعادة تشغيله من لوحة التحكم.
- لا توجد نسخ احتياطية يومية مضمونة في الخطة المجانية.
- عند نمو الموقع قد تحتاج خطة Pro (تبدأ نحو 25 دولاراً شهرياً) للنسخ الاحتياطية وسعة أكبر ودون إيقاف.
- تكاليف أخرى محتملة لاحقاً: نطاق (دومين) خاص، خدمة بريد إرسال للتنبيهات، ورسوم بوابة الدفع إن فعّلتها مستقبلاً (غير مفعّلة الآن).
- Cloudflare Pages المجاني يكفي غالباً للبداية.

## 8) مشاكل شائعة
- الموقع لا يعرض بيانات من Supabase: تأكد من اسم المتغيرين بالضبط وأعد النشر.
- خطأ permission denied: غالباً الحماية (RLS) تعمل بشكل صحيح؛ المحتوى غير المنشور لا يظهر للزوار.
