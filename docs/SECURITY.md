# قائمة فحص الأمان — Cycling AE

## قبل الإطلاق
- [ ] RLS مفعّل على كل الجداول (Table Editor يظهر علامة RLS على الجميع).
- [ ] لا يوجد أي مفتاح service_role في الكود أو `.env` المرفوع أو Cloudflare متغيرات الواجهة (`VITE_*`).
- [ ] ملف `.env` غير مرفوع إلى Git؛ `.env.example` يحوي أسماء فقط.
- [ ] أول مدير عُيّن عبر SQL يدوي (docs/BACKEND_SETUP.md) وليس بأول تسجيل.
- [ ] جدول user_roles لا يقبل كتابة من التطبيق (جرّب: مستخدم عادي يحاول الإدراج فيُرفض).
- [ ] المستخدم العادي لا يستطيع نشر مسار أو إعلان أو تقييم بنفسه (الحالة تبقى pending/draft حتى يوافق مدير).
- [ ] المستخدم لا يستطيع إنشاء اشتراك لنفسه (جدول subscriptions للمدير/الخدمة فقط).
- [ ] admin_audit_logs: إضافة وقراءة للمدراء فقط، بلا تعديل أو حذف.
- [ ] مجلدات الصور: حد 5 ميغابايت، JPEG/PNG/WebP فقط؛ صور المستخدمين داخل مجلد باسم معرّفهم فقط.
- [ ] تأكيد البريد الإلكتروني مفعّل، وSite URL وRedirect URLs مضبوطة على نطاقك فقط.
- [ ] الصور لها حقوق موثقة (حقلا credit وlicense).
- [ ] لا أرقام مسافات أو ارتفاعات مختلقة: الأرقام فارغة حتى التحقق (source + verified_at).
- [ ] لا دفع حقيقي: لا تُخزَّن بيانات بطاقات إطلاقاً.

## بعد الإطلاق
- [ ] راجع Authentication ثم Users دورياً وتأكد من قائمة المدراء: `select * from public.user_roles;`
- [ ] راجع admin_audit_logs أسبوعياً.
- [ ] فعّل التنبيه على اقتراب حدود الخطة المجانية.
- [ ] خذ نسخة احتياطية يدوية (Dashboard) قبل أي تعديل كبير على الجداول.
- [ ] عند ظهور مفتاح مسرّب: Project Settings ثم API ثم أعد توليد المفاتيح وحدّث Cloudflare.
- [ ] عند إضافة دفع لاحقاً: استخدم مزوداً خارجياً مع Webhook على خادم فقط، وسر الدفع لا يوضع في الواجهة.

## مخاطر معروفة
- مفتاح anon عام بطبيعته؛ الحماية الفعلية هي سياسات RLS فقط، فلا تعطّلها.
- الإعلانات المستعملة لا تخزن أرقام تواصل علنية؛ يجب تصميم قناة تواصل آمنة لاحقاً.
- تقارير الإساءة وحدود المعدل (rate limits) غير موجودة بعد.
